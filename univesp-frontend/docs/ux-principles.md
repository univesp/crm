# UX Principles

## Sistema de Atendimento da Univesp

## 1. Objetivo

Definir os principios de experiencia do usuario para aluno, OP e admin, priorizando:

- orientacao guiada
- reducao de erro
- rapidez de entendimento
- acessibilidade
- baixa carga cognitiva

---

## 2. Principio central

O sistema deve ser o mais guiado possivel.

O usuario nao deve precisar "descobrir" o que fazer.
A interface deve conduzir o proximo passo com clareza.

---

## 3. Principios gerais de UX

### 3.1. Guiar antes de abrir protocolo

Antes de abrir atendimento humano, o sistema deve:

- mostrar o tema principal
- mostrar o subtema
- apresentar resposta oficial
- perguntar se resolveu

### 3.2. Registrar tudo

Mesmo quando a FAQ resolve, o atendimento deve ser registrado internamente.

### 3.3. Reduzir liberdade cedo, abrir liberdade depois

No comeco:

- arvore guiada
- escolhas simples
- FAQ objetiva

Depois:

- descricao livre
- anexos
- interacao humana

### 3.4. Deixar o status sempre claro

O usuario deve saber sempre:

- onde esta
- o que ja aconteceu
- o que falta
- quem deve agir agora

### 3.5. Usar linguagem simples

Especialmente na visao do aluno:

- frases curtas
- termos conhecidos
- instrucoes objetivas
- evitar jargao interno

### 3.6. Tornar o sistema previsivel

A mesma acao deve ter o mesmo comportamento em todas as areas.

---

## 4. UX por perfil

### 4.1. Aluno e ex-aluno

Prioridades:

- entrada simples
- arvore curta
- resposta objetiva
- protocolo facil
- acompanhamento intuitivo

O aluno deve sentir que:

- foi entendido
- sabe onde esta seu caso
- sabe o que precisa fazer

### 4.2. OP

Prioridades:

- fila clara
- prioridade e SLA evidentes
- leitura rapida do caso
- painel lateral com FAQ operacional
- acao rapida

O OP deve sentir que:

- sabe o que verificar
- sabe o que responder
- sabe quando escalar

### 4.3. Admin e gestao

Prioridades:

- visao macro
- filtros e indicadores
- controle de filas
- edicao de FAQ
- controle de criticidade e permissoes

A gestao deve sentir que:

- controla o sistema
- enxerga gargalos
- consegue melhorar processo

---

## 5. Padrao de navegacao

### 5.1. Aluno

Fluxo ideal:

1. acesso unificado
2. sistema de atendimento
3. tema
4. subtema
5. resposta da FAQ
6. resolveu ou nao resolveu
7. protocolo
8. acompanhamento

### 5.2. OP

Fluxo ideal:

1. fila
2. abertura do caso
3. leitura do historico
4. FAQ operacional
5. acao
6. encerramento ou escalonamento

### 5.3. Admin

Fluxo ideal:

1. dashboard
2. filtro por area
3. caso critico ou fila
4. acao
5. auditoria, melhoria ou parametrizacao

---

## 6. Regras de UX guiada

- sempre mostrar o proximo passo mais provavel
- evitar telas com muitas decisoes simultaneas
- destacar o botao principal
- explicar quando uma acao gera protocolo
- explicar quando o caso sobe de nivel
- mostrar timeline do atendimento
- destacar pendencias do usuario
- mostrar evidencias e anexos de forma clara

---

## 7. Acessibilidade aplicada a UX

- toda tela deve funcionar por teclado
- foco deve ser visivel
- formularios devem ter label
- mensagens de erro devem ser compreensiveis
- conteudo nao deve depender so de cor
- o sistema deve tolerar zoom e aumento de fonte
- a linguagem deve ser compreensivel

---

## 8. Resultado esperado

A UX do sistema deve ser:

- orientada
- simples
- previsivel
- auditavel
- inclusiva
- institucional
